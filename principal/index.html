03 / Selected decisions

Architecture under pressure.

Four case studies framed around the decision, the system pattern, and the measured result—not a list of technologies.

Control plane / repeatability / adoption

Metadata-driven ingestion

New titles previously required bespoke pipelines. The architectural move was to express a title as configuration and make validation, observability, and deployment controls part of the framework.

Constraint

Different telemetry shapes and local ownership across title teams.

Decision

Separate metadata control from runtime execution; standardize the repeatable controls.

Outcome

Onboarding moved from four two-week sprints to one.

“Platforms beat projects when the pattern repeats.”

Open format / migration patterns / optionality

Apache Iceberg modernization

Legacy external tables were costly, slow, and optimized around a single engine. The response: an open table format with repeatable migration patterns and shared quality, metadata, and security controls.

Constraint

Performance drag, cost pressure, and engine lock-in.

Decision

Adopt Iceberg and codify the migration path across more than 100 data objects.

Outcome

Query time and compute cost fell 40–50%, with multi-engine readability.

Open architecture is useful when the operating model is equally deliberate.

Certified metrics / semantic models / governed AI

Semantic layer & conversational analytics

Different titles defined metrics differently. The reporting product standardized definitions first, then exposed certified metrics through two AI-ready semantic models and a cached MCP tool layer.

Constraint

Cross-title metrics lacked consistency and analyst trust.

Decision

Ground natural-language questions in semantic contracts—not raw tables.

Outcome

80+ analysts use the system for 200+ questions per day.

AI on messy data gives the wrong answer faster. The semantic layer comes first.

Workload design / telemetry / ownership

Platform cost optimization

Snowflake spend was growing faster than usage. Workloads were rebalanced, retention tightened, and cost telemetry put in front of the teams making consumption decisions.

Constraint

Cost growth without clear ownership at the point of consumption.

Decision

Combine architectural levers with transparent, team-level cost signals.

Outcome

$800K annual savings—about 30%—sustained year over year.

Visibility changes behavior faster than rules do.

06 / Operating principles

How I make architecture real.

  1. 01

    Start with the repeated decision.

    Find where teams repeatedly spend judgment and engineering time; that is where a platform earns its place.

  2. 02

    Prototype the path.

    Use MVPs and reference implementations to expose trade-offs before asking teams to adopt a standard.

  3. 03

    Protect local context.

    Standardize what creates measurable value while preserving the domain knowledge that makes each product distinct.

  4. 04

    Measure the system.

    Treat quality, adoption, latency, and cost as feedback signals—not as separate after-the-fact controls.
